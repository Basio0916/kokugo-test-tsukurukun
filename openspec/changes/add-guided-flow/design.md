## Context

動機と範囲は proposal.md、振る舞いは specs を参照。

いまの作り:
- 会話のメッセージはデータで持ち、ボタンを押すと App が実行する（`src/chat/`）。確定の状態（`confirmed`）・作っている大問（`drafting`）・要確認（`flags`）は App が持つ
- 紙面の操作（`onSection`・`onQuestion`）は、紙面の割り付けを測り直さないよう `useCallback` で固定し、テストを関数で更新している
- 配点をそろえる（`rescalePoints`）は全部の小問を割り直し、App はそのあと確定をすべて外している

## Goals / Non-Goals

**Goals:**
- 次にすること・大問の状態を、テストと状態から決める純粋な関数にして、案内と一覧で同じ判定を使う
- 案内は「確定した」「作り始めた」できごとをきっかけに一度だけ出す（状態から毎回判定し直して何度も出さない）

**Non-Goals:**
- AI が案内の文を作ること（決まった文で出す）

## Decisions

### 1. 次にすることと大問の状態は `src/chat/guide.ts` の純粋な関数
- `nextStep(test, { compositionOffered })` は、本文待ちの最初の大問 → 漢字待ちの大問 → 作文の提案（作文がなく、まだ勧めていない） → そろった、の順に一つ返す。
- `sectionStatus(section, { drafting, flags, confirmed })` は一覧の状態を返す。
- 代替案: App の中で毎回条件を書く。案内と一覧で判定がずれる。

### 2. 案内はできごとから出す
- 作り始め（`start`）と確定（会話のボタン・紙面の「確定する」）で `nextStep` を呼び、メッセージを足す。作文を勧めたかは App の状態に持つ。

### 3. 紙面の操作はテストの最新を読んで、前と後を会話に残す
- `onSection`・`onQuestion` は `testRef` から今のテストを読み、変えたテストを `commit` し、前と後を持つメッセージ（「元に戻す」）を足す。`useCallback` の依存は変えず、参照するのは ref と状態を変える関数だけにする。
- 確かめの問い（`window.confirm`）はやめる。消しても元に戻せるため。
- 傍線部の順と問の順のずれは、各小問が最初に参照する傍線部の番号が問の順に増えているかで見る。

### 4. 作文を足すときは、作文の配点を残してそろえる
- `rescalePoints(test, fixed)` に、配点を変えない大問の識別子を渡せるようにし、残りを `満点 − 変えない大問の配点` に割り直す。作文の配点は、ほかの大問を足すときと同じ枠（同じ種類の大問の枠、なければ十点）。

### 5. 一覧は紙面の上に置き、押すとそのブロックへ移る
- 紙面のブロックに大問・小問の識別子（`data-section`）を付け、一覧から `scrollIntoView` で移る。解答用紙・模範解答のタブを開いていたら、先に問題用紙のタブにする。
- 「＋ 大問を追加」は合計の欄から一覧に移す（同じボタンが二つ並ばないように）。

## 確認してほしい判断

- 紙面で消したときの確かめの問いをやめ、会話の「元に戻す」で戻すようにした（モックと同じ）
- 作文を勧めるのは一度だけ。作文の配点は、ほかの大問を足すときと同じ枠（なければ十点）にし、ほかの配点を満点に合わせ直す
- 配点を満点にそろえても、大問の確定は外さないことにした（今までは全部外していた）
- 案内と一覧は決まった文で出し、AI には作らせない
- 解答用紙の破線は画面だけにし、印刷では実線にした

## Risks / Trade-offs

- [会話のメッセージが増えて流れが長くなる] → 紙面の操作は一行の知らせにし、ボタンは元に戻すだけにする
- [紙面で消したものを、会話を見ずに見失う] → 消したことを会話に出し、合計の欄も変わるので気づける

## Migration Plan

- データの形は変えない
