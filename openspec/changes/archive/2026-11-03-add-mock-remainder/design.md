## Context

突き合わせ表の未対応の八行は、どれも今ある画面の小さな直しで済む。新しいサーバー関数は足さない（Vercel Hobby の関数の上限 12 に対して 10 のまま）。

## Goals / Non-Goals

**Goals:**
- 突き合わせ表の未対応の行をなくし、モックと同等にする

**Non-Goals:**
- モックが会話で行っていたこと（大問を足す候補を会話に並べる）を、会話に移すこと。今のポップアップで選ぶ形のまま、選べるものをモックにそろえる

## Decisions

### 1. 変換中の Enter は、ネイティブのイベントの `isComposing` で見る
- React の合成イベントには変換中かどうかがないので、`e.nativeEvent.isComposing` を見る。

### 2. 大問を足す位置は、最初の作文の大問の前
- 足す処理を「作文の前に入れる」に変える。作文を足すとき（作文がないときだけ足せる）は最後に入れる。
- 足す画面には、テストに入っている文章の教材の名前・漢字・作文・文法の教材の名前を渡し、それらの選択肢を選べなくして「（入っています）」と添える。

### 3. 選択肢の数の知らせは、直す画面の中で出す
- 選択肢の欄の行の数が開いたときと違えば、正答の欄の上に「選択肢の数が変わりました。正答の記号を確かめてください。」と出す。正答が範囲の外になったら、その場でアに戻す。

### 4. 背景で閉じるのは、押し始めと離したところの両方が `<dialog>` そのもののとき
- `<dialog>` の中身を内側の要素で包み、`mousedown` と `click` の対象が両方とも `<dialog>` 自身（背景）のときだけ閉じる。

### 5. 線を引いて作る案は、形式の選択と字数の確定で整え直す
- 形式の `change`、字数の `blur` と Enter で整え直す。字数は記号選択のときも直せるようにして、記号選択のときは字数だけ変えても頼まない（形式を変えたときに、その字数で頼む）。
- 頼むたびに番号を振り、届いた返答が最後に頼んだものでなければ捨てる。

### 6. 動きを減らす設定は、CSS と JS の両方で見る
- CSS は `prefers-reduced-motion: reduce` で切り替えの動きを止める。一覧から移るときのスクロールは、その設定なら `behavior: 'auto'` にする。

## 確認してほしい判断

- 大問を足す画面では、テストに入っている教材・漢字・作文・文法の教材を選べなくした（モックは会話で「もう入っています」と断っていた）
- 選択肢の数が変わったことは、決めたあと会話で知らせるのではなく、直す画面の中で決める前に知らせる（モックは決めたあと会話で知らせていた）
- ポップアップの外を押して閉じたときは、直しかけた内容は入れずに捨てる（「やめる」と同じ）
- 線を引いて作る案は、形式は選んだとたん、字数は欄を離れたときに整え直し、「整え直す」ボタンはなくした（モックと同じく、変えるたびに AI に頼む。一回およそ十秒）
- 試験時間の知らせは、四十五分より短くしたときだけ添える（モックと同じ境目）

## Risks / Trade-offs

- 形式を何度も選び直すと、そのたびに AI に頼む → 最後に頼んだものだけを入れ、整え直している間は「AI が問い文を整え直しています」を出す
