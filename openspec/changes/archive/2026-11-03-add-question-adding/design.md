## Context

動機と範囲は proposal.md を参照。

いまの作り:
- 文章の大問の生成（`src/ai/draft.ts`）は、AI の返答（`SectionProposal`: 引用した傍線部と小問の並び）を `toSection` で大問に組み立てる。傍線部を付ける `anchorMarks` は、本文の傍線部をいったん全部外してから付け直す
- Claude の呼び出しと一度だけの作り直しは `draftWithRetry`（`src/ai/claude.ts`）にまとまっている
- 紙面の上での操作（`src/edit/`）は純粋な関数で、小問を直すポップアップ（`QuestionEditor`）は空でない小問を前提にしている
- 紙面はブロックを測って詰める。操作の表示はブロックの中に重ね、割り付けの幅に入れない

## Goals / Non-Goals

**Goals:**
- 三つの AI の足し方（おすすめ・形式・線を引く）を、一つの返答の形と一つの関門で扱う
- すでにある傍線部と小問を壊さずに足す

**Non-Goals:**
- チャットからの追加（続く change で、ここで作る関数を使う）
- 漢字・文法の大問への AI の案

## Decisions

### 1. 返答の形は「小問一つ＋その小問の傍線部」の案の並び（`src/ai/addQuestion.ts`）
- `QuestionIdeas = { ideas: [{ marks, question, rationale, adjustments? }] }`。`marks` と `question` の形は文章の大問の生成（`ProposedMark`・`ProposedQuestion`）と同じものを使う。おすすめは三つ、形式・線を引くは一つ。
- サーバーは案ごとに、傍線部を付けた本文と、テストのデータとして検証した小問を返す。画面は選んだ案の本文と小問をそのまま入れる。
- 代替案: 足し方ごとに別の返答の形にする。中身は同じ「小問と傍線部」で、検証と変換を三つ書くことになる。

### 2. 要求は足し方で分けた判別付きの形にする（`api/draft-question.ts`）
- `how: { kind: 'suggest' } | { kind: 'format', format, aim? } | { kind: 'mark', quote, wish }`。共通の項目（学年・教材名・刻み・大問）は外に置く。
- 代替案: 足し方ごとに関数を分ける。共通の項目と処理が同じで、指示文だけが違う。判別付きの形なら、組み合わせの正しさは型で守れる。

### 3. すでにある傍線部を残して引用を付ける（`addMarks`）
- 本文の今の傍線部の範囲を求め、引用がすでにある傍線部と同じ範囲ならその識別子を使い、一部だけ重なるなら不正、重ならなければ新しい識別子で付ける。新しい識別子は今ある識別子と重ならないものにする。
- 代替案: 今の `anchorMarks` で全部付け直す。今ある小問が参照している傍線部が外れてしまう。

### 4. 足した小問の配点
- 足した小問の配点は、その大問の今の小問の配点の平均を刻みの倍数に丸めたもの（小問がなければ配点の枠を五問で割ったもの。最低でも刻み）。合計が満点からずれたら、配点の合計の表示で知らせ、「配点を満点にそろえる」で直してもらう。
- 代替案: 足すたびに大問の配点を割り直す。先生が直した配点が勝手に変わる。

### 5. 本文の選択から引用と直前の文字を取る
- 紙面の本文の選択（`Selection`）が一つの大問の本文の中にあるとき、選んだ文字列と、選択の始まりより前の同じ段落の数文字を取り、引用（`quote`）と直前の文字（`before`）にする。画面外の測るためのブロックは選択の対象にしない。
- 代替案: 選んだ文字列だけを送る。本文に同じ文字列が二回出てくると決まらない。

### 6. 画面
- 「＋ 小問を追加」は、大問の見出しと各小問のブロックの左の余白（段落の後ろの余白）に重ねる。押すと足し方を選ぶポップアップ。
- おすすめは案を三つ並べ、押すとすぐ入る。形式・線を引くは、AI の案を `QuestionEditor` で開き、「この問題で入れる」で入れる。自分で書くは、形式ごとの空の小問のひな形を `QuestionEditor` で開く。`QuestionEditor` は、空の項目を書く欄を出せるようにする。

## 確認してほしい判断

- AI を使う足し方は、本文を持つ文学的文章・説明的文章の大問でだけ使える。漢字・文法の大問は「自分で書く」だけ。
- おすすめの案は三つ。押すとすぐ入る（入れる前に直す画面は挟まない。入れたあとに「直す」で直せる）。
- 形式を選んで作ってもらう案と、線を引いて作る案は、入れる前に直す画面で示す。
- 足した小問の配点は、その大問の小問の配点の平均（刻みの倍数に丸める）。合計が満点からずれても自動ではそろえない。
- 本文に同じ文字列が二回以上出てきて決まらないときは、もっと長く選ぶよう知らせる。

## Risks / Trade-offs

- [縦書きの本文の選択が、ブラウザによってうまく取れない] → Chrome / Edge を基準にし、選択が本文の外にはみ出したら知らせる。
- [AI の案が今ある小問と重複する] → 今ある小問を AI に渡し、重複しないよう指示する。おすすめは三つから選べる。
- [足すたびに配点の合計がずれる] → 合計の表示で知らせ、そろえ直しを用意している。

## Migration Plan

- 保存しているデータはないので、移行はない。PR のプレビューで足し方を確かめる。マージはユーザーに任せ、問題が出たら revert する。
