## Context

アプリはいまサンプルのテスト（`src/sample/sampleTest.ts`）を開いて描くだけで、AI に大問を作ってもらえるのはサンプルの走れメロスの大問に限られる（`add-ai-section-draft`）。単元データ（`src/catalog/`）には一〜三年の教材のまとまり（配当月・教材名・時数・指導事項の記号）がある。

いまの作りの制約:
- AI の生成（`draftSection` / `toSection`）は、大問の小計を、大問が持っている小問の配点の合計から求めている。小問のない骨組みの大問では 0 になり、配点を割り振れない
- 本文は一つの段落として描かれ、改行は消える（`Prose` は `<p>` が一つ）
- 紙面の内側は `overflow: hidden` なので、一枚に収まらない本文は、何も知らせずに切れる
- 画面の状態は「作っている大問は一つだけ」の形（`DraftState`）

締め切りは 2026-11-08 20:00。この change は一日で終え、漢字・文法の AI 生成は続く change で足す。

## Goals / Non-Goals

**Goals:**
- 単元を選ぶ → テストの情報 → 骨組み → 本文を貼る → AI が作る → 紙面、を一通り動かし、デプロイする
- 協力者（現役の先生）が自分の教材の本文で試せるようにする

**Non-Goals:**
- 漢字・文法の大問の AI 生成（続く change）
- 古文・漢文の大問（古文は項目を持つ問い（現代仮名遣い）とルビ、漢文は返り点が要るので後で）、作文の大問
- 配点の枠や大問の並びの手直し、小問の編集、保存（後の change）
- 本文を複数ページに分けて流すこと

## Decisions

### 1. 画面の切り替え
- `App` は二つの場面を持つ: 作り始めの画面（`start`）と紙面（`paper`）。アプリを開くと `start`。
- サンプルは URL の `?sample`（今の `?sample=long` も残す）で紙面を直接開く。作り始めの画面の「サンプルを見る」はこの URL へのリンクにする。既存の E2E はこの URL を開くように変える。
- 画面の状態は保存しない（再読み込みで作り始めに戻る）。保存は後の change。

### 2. 教材の一覧と種類の分類（`src/start/kinds.ts`）
- 一覧に出すのは、読むことの指導事項（`C(1)…`）を持つまとまり。教材名はまとまりの最初の教材名（例: 「走れメロス」）を使う。
- 大問の種類は、こちらの判断による分類なので、単元データ（資料の事実）とは別のファイルに置く: 説明的文章の教材名の一覧、古文・漢文の教材名の一覧を持ち、どれにも当たらなければ文学的文章とする。古文・漢文は一覧に出すが選べない（「後で対応」）。
- 一覧の並びは単元データの順（年間指導計画の順）。単元名と配当月を添える。

### 3. 骨組みと配点の枠（`src/start/skeleton.ts`）
- 選んだ教材ごとに、種類・指示文・識別子だけを持つ大問を作る（本文も小問もない）。
- 配点の枠は、`allocatePoints`（`src/ai/points.ts`）で、各大問に同じ重みを付けて満点を割り振る。どれも刻みの倍数で、合計は満点ちょうど。
- 配点の枠は、テストのデータではなく画面の状態（大問の識別子 → 点数）として持つ。小問ができた後の小計は小問の配点から求まるので、テストのデータに二つ目の「小計」を持たせない。

### 4. 本文を貼る前の大問（`test-model` の変更）
- `Section` のスキーマを、文学的文章・説明的文章・古文の大問は「本文と小問の両方を持たない」ことを許すように緩める。本文がないのに小問がある場合は今まで通り不正。
- 紙面では、本文のない大問の見出しに配点の枠を描き（`Paper` に配点の枠を渡す）、本文の代わりに本文欄（点線の枠と「本文を貼り付けてください」）を描く。本文欄は画面では押せる。印刷では空の枠として出る。

### 5. 段落の区切り
- 本文の区切りの種類に `break`（段落の区切り）を足す。貼り付けた本文は、改行で段落に分け、空の行を捨て、段落の頭の空白（全角・半角）を取り除いて、段落の間に `break` を入れる。
- 紙面は `break` で `<p>` を分ける（段落ごとに一字下げ）。
- AI に渡す本文は段落を改行でつないだ文字列にする（`plainText` は `break` を改行にする）。傍線部の引用が改行をまたぐ場合は不正とする（`anchorMarks`）。

### 6. 本文を貼る画面（`src/start/PastePassage.tsx`）
- `<dialog>` に、本文の入力欄（複数行）と作者名の入力欄を置く。決めると、出典を「作者「教材名」より」（作者名がなければ「「教材名」より」）にして本文を入れ、そのまま AI に作ってもらう。
- 教材名は出典の「」から読むので（`materialOf`）、AI の生成は今の作りのまま教材を見つけられる。

### 7. AI の生成の変更
- 要求に配点の枠（`subtotal`）を足し、`draftSection` と `toSection` は、大問の小問からではなく、この値で配点を割り振る。サンプルのように骨組みから作っていない大問は、今の小計を送る。
- 画面の状態を、大問ごとの状態（大問の識別子 → 作っている／作った（理由の一覧）／作れなかった（理由））に変える。ボタンは作っている大問だけ押せなくする。
- 理由の一覧は、作った大問ごとに出す。

### 8. 一枚に収まらない本文
- `Paper` は割り付けのために各ブロックの幅を測っている。本文を含むブロック（大問の見出し＋本文）の幅が紙面の内側の幅を超えたら、その大問の識別子を画面に知らせ、紙面の外に「本文が一枚に収まりません。範囲を短くしてください」と出す。
- 目安の字数は測ってから、本文を貼る画面にも書く（B4 横一枚に、本文の枠でおよそ何字入るか）。測ると、段落一つで約 2,330 字、段落十で約 2,190 字まで収まったので、画面には「二千字ほどまで」と書く。

### 9. テスト
- 単体: 骨組みと配点の枠、本文の貼り付けの変換（段落・空の行・字下げ・出典）、教材の種類の分類、`Section` の緩めたスキーマ、`toSection` が配点の枠で割り振ること、引用が段落をまたぐと不正になること。
- E2E（API は固定の返答に差し替え）: 二年で走れメロスを選び、テストの情報を入れて作る → 本文欄 → 貼り付け → 作っている表示 → 小問に置き換わる。教材を選ばないと作れない。長すぎる本文で知らせが出る。サンプルを見る。既存の紙面の E2E はサンプルの URL で通す。

## Risks / Trade-offs

- [教材名だけで種類を分けるので、分類が外れる教材がある] → 説明的文章・古文・漢文の一覧を、二年は確かめて作る。外れても大問の種類の違いは指示文と AI への指示に出るだけで、後で直せる。
- [配点の枠を同じ重みで割るのは、実際のテストの配点と違う] → 後の change で先生が直せるようにする。この change では合計が満点になることを守る。
- [長い本文を貼られる] → 切れずに知らせる。分けて流すことはしない。
- [一日で終わらない] → 段落と長さの知らせは、本文の貼り付けの後に回し、最初に「選ぶ → 骨組み → 貼る → 作る」を通す。
