## Context

動機と範囲は proposal.md、振る舞いは specs を参照。

いまの作り:
- 紙面のブロックは Paper が描く。選んだもの・変わったもの・要確認の印は、ブロックの外側の要素の class で付けている（割り付けには関わらない）
- 線を引いて作る（`MarkQuestion`）は、希望を AI に渡して案を一つ受け取り、入れる前に直す画面（`QuestionEditor`）で示す。要求の `how: { kind: 'mark', quote, before, wish }`
- 本文の選択は `mouseup` で読む

## Goals / Non-Goals

**Goals:**
- どれも画面の作りだけで足し、割り付け（幅の計測）を変えない

**Non-Goals:**
- 紙面のすべての操作をキーボードだけで行えるようにすること（選ぶことだけ）

## Decisions

### 1. 確定していない大問を薄く描くのは、ブロックの外側の要素の class で行う
- Paper に確定した大問の集合を渡し、確定していない大問の小問のブロックに `blk-prop` を付ける。色だけを変えるので割り付けは変わらない。印刷では外す。

### 2. キーボードで選ぶ
- 大問・小問のブロックの外側の要素に `tabIndex=0` と、Enter・Space で選ぶ処理を付ける。名前は「【三】問二を選んで相談する」。ブロックの中に操作のボタンがあるので、役割は `button` でなく `group` にする（ボタンの中にボタンを入れない）。

### 3. 上に残す欄は sticky で並べる
- 合計の欄・一覧・タブを一つの欄にまとめ、紙面の列の中で `position: sticky; top: 0` にする。

### 4. タッチの選択は `touchend` でも読む
- `mouseup` と同じく、少し待ってから本文の選択を読む。

### 5. 線を引いて作る案の整え直しは、要求に形式と字数を足す
- `how: { kind: 'mark', ..., format?, charLimit? }` を足し、AI への指示に「解答形式は◯◯、字数は◯字にする」と書く。直す画面の上に、形式と字数の欄と「整え直す」「書き直して、もう一度整えてもらう」を出す（`QuestionEditor` に上に足す欄を渡せるようにする）。
- 書き直すときは、選んだ箇所と書いた希望を残して `MarkQuestion` を開き直す。

## 確認してほしい判断

- 確定していない大問は、問題用紙では小問だけを薄くし、見出しと本文は普通の濃さのままにした（モックと同じ）
- キーボードで選べるのは大問の見出しと小問だけにした（本文の文字を選んで線を引くのはマウスかタッチ）
- 形式と字数を選び直したときは、ボタン（整え直す）を押したときだけ AI に頼む（モックは選んだとたんに整え直していた）
- 作文の問は、解答用紙と模範解答で「作文」と書き、問題用紙では今までどおり見出しなしで条件を並べる
- 上に残すのは、配点の合計の欄・大問の一覧・紙のタブ（モックの設定の欄は「テストの情報を変える」の中）

## Risks / Trade-offs

- [上に残す欄が高くなり、狭い画面で紙面が見えにくい] → 欄は折り返して並べ、紙面の列の中だけで残す
