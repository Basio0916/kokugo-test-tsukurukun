## Context

光村図書のサイトで公開されている令和7年度版の資料（一〜三年の「年間指導計画例」と「指導事項配列表」、PDF と Word）は、`docs/sources/mitsumura-r7/` に保存済みで、`.gitignore` で git の対象から外してある。サイトの利用規約は、ダウンロードが明確に許可された資料の複製を認めている。

年間指導計画例の Word は、一つの学年が三つほどの表に分かれている。表の行は二種類ある。
- 単元の見出しの行: セルが一つだけ（横に結合）で、「１　広がる学びへ」「情報×SDGs」のように単元名を持つ
- 教材のまとまりの行: 五列。月 ｜ 教材名・時数・目標 ｜ 時（次）｜ 学習活動 ｜ 評価規準

二列目は改行区切りで、先頭から教材名が続き、「　８時間（読⑥書②）」の行で時数、その後に「◎…（知・技(1)エ）」「◎…（思・判・表C(1)イ）」のような目標の行が続く。言語活動例の行（「（思・判・表C(2)イ）」）と、「（学びに向かう力、人間性等）」の行もある。一つのまとまりに複数の教材（走れメロス＋［書く］…＋漢字に親しもう５）が入ることがある。

小問の `standard` はすでに `(1)ウ` `C(1)イ` `C(1)オ・B(1)ウ` の形で書いている（`src/sample/sampleTest.ts`）。

## Goals / Non-Goals

**Goals:**
- 一〜三年の単元と教材のまとまりを、資料の順のまま、事実情報だけでデータにする
- 指導事項の記号を、小問の `standard` と同じ書き方で持つ
- 学年と記号から学習指導要領の指導事項の文言を引けるようにする
- データを作る手順を再現できるようにする

**Non-Goals:**
- 単元選びの画面（後の change）
- ジャンルや「どの大問の種類に使えるか」の分類。資料にない、こちらの判断による分類なので、事実のデータと分けて、使う change（単元選び）で決める
- 指導事項配列表（教材×指導事項の表）のデータ化。年間指導計画例と内容が重なるので、照らし合わせの確認にだけ使う
- 他社の教科書

## Decisions

### 1. 資料は Word 版から Python のスクリプトで読み、生成した JSON をコミットする
- Word（docx）は表の構造（行・セル・結合）がそのまま残るので、PDF の文字抽出より確実に読める。docx は zip の中の XML なので、Python の標準ライブラリ（`zipfile`、`xml.etree`）だけで読める。
- スクリプトは `scripts/extract_mitsumura_units.py` に置く。資料のパスを引数で受け取り、`src/catalog/mitsumura-r7.json` を書き出す。資料はリポジトリにないので、アプリのビルドやテストではスクリプトを動かさない。生成した JSON をコミットし、アプリはそれを読む。
- スクリプトを残すのは、取り出し方に誤りが見つかったときに作り直せるようにするため（データの出どころの記録にもなる）。
- 代替案: Node で docx を読む。zip を読むライブラリの追加が要る。手で JSON を書く。三学年で七十件前後あり、写し間違いが出る。

### 2. データの形
```
Catalog {
  textbook: "光村図書 令和7年度版 国語"
  sources: [{ title, url, retrieved }]   // 出典（資料名・URL・取得日）
  grades: [{ grade: 1|2|3, units: Unit[] }]
}
Unit { title: string | null, groups: Group[] }      // title が null = 単元より前の教材
Group {
  month: 4..3（4〜12, 1〜3）
  materials: string[]          // 教材名。資料の表記のまま（［書く］なども含む）
  hours: number                // 時数
  breakdown?: string           // 内訳（例: "読⑥書②"）。資料の表記のまま
  standards: string[]          // 指導事項の記号（(1)エ, C(1)イ …）。資料の順、重複なし
  activities: string[]         // 言語活動例の記号（C(2)イ …）
  earlierGradeCodes?: { grade, code }[]  // 前の学年の記号（資料の「1年(1)エ」「2年思・判・表B(2)ウ」）
}
```
- 単元名は見出しの表記のまま（「４　人間のきずな」）持つ。番号を分けて使う場面がまだないので分けない。
- 教材名は教材欄の行ごとに持つ。資料で折り返された行（「[聞く]」だけの行、「――「徒然草」から」のような副題、「／」で終わる行）は一つにまとめる。題と副題が別の行に書かれた教材（「文法への扉１」「単語をどう分ける？」）は、資料の行のまま別の要素になる。
- 一つの欄に、時数を付けた教材が複数並ぶ行がある（三年の「温かいスープ」「アラスカとの出会い」など）。時数の行で区切り、別のまとまりにする。
- 記号の外側の括弧は、資料に全角と半角が混ざっているので、どちらも読む。
- 記号の形は zod で検証する: 指導事項は `^(\([123]\)[ア-カ]|[ABC]\(1\)[ア-オ])$`、言語活動例は `^[ABC]\(2\)[ア-ウ]$`。「学びに向かう力、人間性等」は記号ではないので入れない。
- 全角数字（「８時間」）は半角に直して数値にする。
- 季節のしおりのように時数の行がないまとまりは、データに入れない（授業の単元ではなく、テストの範囲にもならない）。

### 3. 指導事項の文言は告示から引く
- 文言は学習指導要領（平成29年告示）中学校国語の各学年の「内容」から引く。告示は著作権の対象外（著作権法13条）。学習指導要領解説は告示ではないので使わない。
- 告示の PDF は欄外の教科名が本文に混ざり、文字を取り出すと項目に分けにくい。そこで、告示の文言を項目ごとに載せている指導事項配列表の見出しから項目と順番を取り、一つずつ告示の本文に含まれることを確かめてから、告示の表記（読点「，」、半角数字）で書き出す（`scripts/extract_standards.py`）。告示に見つからない項目があればスクリプトは止まる。出典は告示とし、URL と取得日を記録する。
- `src/catalog/standards.json` に `{ grade, code, text }` の並びで置く。言語活動例の文言も同じ表に入れる。
- 配列表に載っていない書写の項目（一年・三年の (3)エ、二年の (3)ウ）は入れない。単元データでも使われていない。
- 引く関数は `standardText(grade, code)`。`C(1)オ・B(1)ウ` のような小問の複合の記号は、`・` で分けて一つずつ引けるよう、分ける関数も用意する。

### 4. 取り出しの確かめ方
- 目で見て信じず、既知の答えと突き合わせる単体テストを書く: 二年の走れメロス・扇の的・漢詩の風景・用言の活用の記号（以前に資料を読んで確認済み）。
- 二年の教材数は、以前に確認した「二十三教材」と比べる。数が違えば、数え方（まとまり単位か、教材名単位か、季節のしおりを含むか）の違いを説明できるようにし、無理に合わせない。
- 余裕があれば、各まとまりの指導事項の記号を、指導事項配列表の ◎ と照らし合わせる（スクリプトの確認として一度だけ行い、結果を tasks に残す）。

### 5. 置き場所
- `src/catalog/`: `schema.ts`（zod）、`mitsumura-r7.json`、`standards.json`、`catalog.ts`（読み込みと検証、引く関数）、テスト。
- `src/model/` には置かない。テストのデータ（作るもの）と、教科書の単元データ（参照するもの）は別の関心事なので分ける。

## Risks / Trade-offs

- [資料の表の崩れ（結合セル、表をまたぐ単元、全角数字、番号のない単元）で取り出しを誤る] → 二年で見えている崩れをすべてテストのケースにする（番号のない単元、単元より前の教材、表をまたぐ単元、全角数字、［書く］などの接頭辞）。
- [教材の一覧を教科書の順に丸ごと持つことが、教科書の編集（素材の選び方・並べ方）を写すことにあたるか] → 事実情報だけで、文章は持たないが、判断はつかない。リポジトリは非公開で、公開するアプリでは単元選びに必要な範囲で表示する。確実を期すなら光村図書の利用許諾の窓口に問い合わせる。
- [告示の文言を写し間違える] → 指導事項配列表の見出しと突き合わせる。
- [時間をかけすぎて、AI の change が遅れる] → この change は半日で終える。手で直す方が早い崩れは、スクリプトに例外として書いてよい。
