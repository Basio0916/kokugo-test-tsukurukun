## Context

動機と範囲は proposal.md、振る舞いは specs を参照。

いまの作り:
- AI の呼び出しは `draftWithRetry`（`src/ai/claude.ts`）にまとまっていて、返答の形を構造化出力で縛り、変換・検証（`Checked<R>`）に通らなければ理由を添えて一度だけ作り直す
- 小問一つの案は `QuestionIdea`（傍線部の引用と小問）で受け取り、`addMarks`（今の傍線部を残して付ける）と `buildQuestion` で小問に組み立てる
- 紙面の上での操作は `src/edit/operations.ts` の純粋な関数で、`Test` を受け取って `Test` か理由を返す
- 大問を作っている状態・理由・失敗は `AiDraftPanel`（`src/AiDraft.tsx`）が紙面の上に並べている
- 紙面はブロックを測って詰め、表示は列の幅に合わせて縮める（`--s`）。測る場所は縮めないので、列が狭くなっても割り付けは変わらない
- どの小問からも参照されない傍線部は、本文に残っても番号が付かず線も引かれない（小問を消したときと同じ）

## Goals / Non-Goals

**Goals:**
- 会話のメッセージの形（本文・気づいたこと・ボタン）を、続く change（本文の食い違いの知らせ）でもそのまま使えるものにする
- 会話から AI に頼む呼び出しを一つにし、AI に渡すテストの読ませ方と関門を一か所にまとめる
- AI に番号を持たせない原則を、会話でも守る（大問・小問は識別子で指す）

**Non-Goals:**
- 会話の保存や、返答を少しずつ出す（ストリーミング）
- 漢字・文法の小問の中身を会話で直すこと

## Decisions

### 1. 会話の状態は App が持ち、メッセージはデータだけにする（`src/chat/`）
- メッセージは `{ who: 'me' | 'ai', text, notes?, buttons?, undo? }`。ボタンは `{ label, action }` のデータ（`confirm`・`redraft`・`undo`・`addSection` など）で持ち、押されたら App が実行する。関数を状態に入れないので、古い状態を閉じ込めない。
- ボタンは押したメッセージのぶんだけ押せなくする（`used`）。モックのように「新しいボタンが来たら前のボタンを全部押せなくする」と、続く change の要確認のボタンが関係ない返答で消えてしまう。
- 作っている間・考えている間の表示は、メッセージではなく状態（大問ごとの作る状態、会話の待ち）から描く。終わったら結果をメッセージとして足す。
- 代替案: 会話を専用のストアや reducer に分ける。今の App は状態を `useState` で並べていて、会話だけ別の仕組みにすると、変更の反映（テストの更新・確定・選択）が二か所に分かれる。

### 2. 「AI と作る」欄を会話に吸収する
- `draft()` は作る状態の管理はそのままに、終わったら会話にメッセージを足す。理由は気づいたこととして並べ、指導事項にない小問に印を付ける。失敗は理由と「もう一度作ってもらう」。本文が一枚に収まらない知らせも会話に出す。
- 「大問を AI に作ってもらう」「出題する漢字を選び直す」のボタンは、大問を選んだときのチップに移す。
- 代替案: 欄を残して会話と並べる。AI からの知らせが二か所に分かれ、モックの「左で相談、右が育つ」にならない。

### 3. 会話の AI 呼び出しは一つ（`api/chat.ts`、`src/ai/chat.ts`）
- 要求: `{ test, selection?, history, message }`。学年はテストの情報から引く。
- AI に読ませるテストは、大問ごとに識別子・種類・教材名・指示文・本文（文章の大問）・傍線部（紙面と同じ番号）・小問（識別子・問の番号・形式・問い文・選択肢と正答・答え・配点・観点・指導事項）を並べた文にする。文章の大問には単元の指導事項の文言も付ける。番号は「紙面でどう見えるか」を伝えるためだけに書き、変更は識別子で返させる。
- 返答の形: `{ reply, notes?, change }`。`change` は `kind` で分けた判別付きの形（`none`・`reviseQuestion`・`redraftSection`・`reorderSections`・`remove`・`addSection`）。構造化出力で判別付きの形が通ることは、手元で本物の Claude を一回呼んで確かめた。
- 並べ替えは「何番目へ動かす」ではなく、すべての大問の新しい並び（識別子の並び）で受け取る。入れ替え・移動のどちらも一つの形で表せ、関門は「並びが今の大問の並べ替えになっているか」だけで済む。
- 代替案: tool use で操作ごとの道具を渡す。一回の返答で変更は一つと決めているので、構造化出力の一つの形で足り、今の `draftWithRetry` をそのまま使える。

### 4. 関門はサーバー側で、変更をテストに当てはめた形まで確かめる
- `reviseQuestion`: 大問が文章の大問で本文を持ち、小問がその大問にあり、項目を持たないこと。傍線部は `addMarks` で付け、小問は `buildQuestion` で元の識別子と配点のまま組み立て、大問として検証する。返すのは直した大問まるごと（本文の傍線部が増えることがあるため）。
- `redraftSection`: 大問が本文を持つ文章の大問であること。サーバーは希望を返すだけで、画面がこれまでの大問を作る流れ（`requestDraft` に希望を添えて）を呼ぶ。会話の呼び出しの中で大問まで作ると、一回の待ちが長くなり、作っている表示や同時に作る扱いも二重になる。
- `reorderSections`・`remove`: 識別子がテストにあること、並びが今の大問の並べ替えであること。
- 通らなければ `draftWithRetry` が理由を添えて一度だけ作り直す。二回とも通らなければ、理由を会話に出す。

### 5. 変更はすぐ入れ、メッセージに「前」と「後」のテストを持たせて元に戻す
- 当てはめる前に、AI に送ったときのテストと今のテストを比べる。直す・作り直すときは対象の大問が送ったときと同じもの（参照が同じ）か、並べ替えは大問の顔ぶれが同じか、消すときは対象があるかを見る。違えば入れずに知らせる。
- 入れたら、メッセージに `{ before, after }` を持たせる。AI に作ってもらった大問の返答にも同じように持たせる。「元に戻す」は今のテストが `after` と同じ（参照が同じ）ときだけ押せる。紙面で何か変えると `after` と違うものになるので、自然に押せなくなる。
- 変わった大問・小問は `changed` として持ち、紙面のブロックに印を付ける。次の変更で入れ替わる。
- 中身が変わった大問の確定は外す。並べ替えは紙面の「上へ・下へ」と同じく確定を外さない。

### 6. 紙面のブロックを選べるようにする（`src/paper/blocks.tsx`）
- ブロックに大問・小問の識別子を持たせ、紙面のブロックのクリックで選ぶ。操作のボタン・「＋ 小問を追加」・本文欄のボタンのクリックと、文字を選んでいるとき（選択範囲が空でない）は選ばない。
- 選んだブロックと変わったブロックには、画面だけの印（`blk-selected`・`blk-changed`）を付ける。印は輪郭と背景だけで、幅を変えないので割り付けは変わらない。印刷では消す。

### 7. 二画面は CSS の grid で並べる
- 左の列（300〜380px）に会話を置き、画面の高さに収めて中だけ送る。右の列に配点の合計と紙面を置く。紙面は列の幅に合わせて縮む今の仕組みのまま。
- 900px より狭い画面では、会話を上、紙面を下に並べる。

### 8. 会話の呼び出しは考える量を抑える
- 会話は待ちが短いほうがよいので、`draftWithRetry` に `effort` を渡せるようにし、会話は `medium` で呼ぶ。大問を作る・小問を足す呼び出しは今の `high` のまま。

## 確認してほしい判断

- 会話で頼んだ変更と、AI が作った大問は、確かめる画面を挟まず、すぐ紙面に入れて「元に戻す」で戻せるようにした（モックと同じくすぐ入れ、元に戻すを足した）。食い違いの知らせ（続く change）は「勝手には直さない」ので、ボタンで先生が選ぶ
- 会話で中身を直せる小問は、文章の大問の小問だけにした。漢字・文法の小問は、大問の作り直し・漢字の選び直しか、紙面の「直す」で直す
- 会話から大問を足すときは、大問を足す画面を開くボタンを返すだけで、どの教材の大問にするかは AI に決めさせない
- 会話は保存しない（再読み込みで消える）。AI に渡すのは直近の数往復だけ
- 「こう伝えてみる」の提案と、スマホでの会話・紙面の切り替えは後回しにした（狭い画面では上下に並ぶ）

## Risks / Trade-offs

- [Opus の返答に十数秒〜数十秒かかる] → 「考えています」を出し、会話は考える量を `medium` に抑える。プレビューで実際の待ち時間を測る
- [AI が選んでいない小問を直す、指す小問を取り違える] → 選んでいる大問・小問の識別子と、紙面での番号を並べて渡す。返答には何をどう変えたかを書かせ、元に戻せるようにする
- [本文が長い大問がいくつもあると、毎回の入力が大きくなる] → 一回あたり一万トークン程度の見込みで、今は全体を渡す。重くなったら、選んでいない大問の本文を省く
- [元に戻した後も、会話の流れには変更したことが残る] → 元に戻したことを先生の操作としてメッセージに残し、AI にも渡る流れに含める
- [二画面で紙面の列が狭くなり、紙面が小さく見える] → 縮める仕組みで収め、狭い画面では上下に並べる

## Migration Plan

- 画面だけの変更で、データの形（`Test`）は変えない。`AiDraft.tsx` を消し、E2E の「AI と作る」欄を前提にした箇所を会話に合わせて直す
- サーバー側の関数を一つ足す（`api/chat.ts`）。環境変数は今のもの（`ANTHROPIC_API_KEY`・`DRAFT_MODEL`）だけを使う
