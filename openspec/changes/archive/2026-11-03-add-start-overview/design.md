## Context

動機と範囲は proposal.md、振る舞いは specs を参照。

いまの作り:
- 作り始めの画面（`StartScreen`）は学年・教材・漢字・文法・テストの情報を選び、決めたときに `buildSkeleton`（純粋な関数）で骨組みを作る
- 単元データのまとまり（`Group`）は、月・時数・指導事項の記号を持つ。指導事項の文言は `standardText` で引ける
- 紙面は、見えない状態で測ると割り付けが崩れるため、開いていない紙は描かない（解答用紙のタブで決めた）

## Goals / Non-Goals

**Goals:**
- 作り始めの画面のプレビューは、決めるときと同じ `buildSkeleton` で作る（見た骨組みと作られる骨組みがずれない）
- 狭い画面でも、紙面の割り付けを崩さない

**Non-Goals:**
- 光村図書以外の教科書の単元データ

## Decisions

### 1. プレビューは選ぶたびに `buildSkeleton` を呼ぶ
- 純粋な関数なので、描くたびに呼んで大問の並びと配点の枠を出す。割り振れないとき（null）は、そのことを出す。
- 指導目標は、選んだ教材のまとまりの指導事項を、記号の頭（(1)〜(3) は知識・技能、A〜C は思考・判断・表現）で観点に分けて並べる。

### 2. 刻みを変えるときは、合わない配点だけでなく全体をそろえ直す
- 刻みの倍数でない配点が一つでもあれば `rescalePoints`（新しい刻み）で満点にそろえる。全部が倍数なら配点はそのまま。
- 代替案: 合わない配点だけを丸める。合計が満点からずれ、もう一度そろえる手間が残る。

### 3. 狭い画面では描く画面を一つにする
- `matchMedia('(max-width: 899px)')` で狭い画面かを見て、「会話」「紙面」の切り替えを出し、選んだほうだけを描く（紙面を隠すのではなく描かない）。会話のメッセージは App の状態にあるので、切り替えても消えない。
- 会話を見ている間にテストが変わったら「紙面」に印を付け、紙面を開いたら消す。会話のボタンで紙のタブ・大問の一覧から移るときは紙面に切り替える。

## 確認してほしい判断

- 作り始めの画面に教科書の選択を出すが、選べるのは光村図書だけにした（ほかは「まだ選べません」と示す）
- 配点の刻みを変えて合わない配点があれば、確かめずに満点にそろえ直す（そろえられなければ変えない）
- 指導目標の観点は、記号の頭で分けた（(1)〜(3) は知識・技能、A〜C は思考・判断・表現）
- 狭い画面の切り替えは、幅 900px 未満で出す
- 観点別の帯は、合計の欄の中に置いた（モックは紙の上の別の欄）

## Risks / Trade-offs

- [狭い画面で会話の入力欄の書きかけが、紙面に切り替えると消える] → 会話の欄を描き直すため。短い頼みを想定し、許す
