## Context

動機は proposal.md、振る舞いは specs（`pdf-export`・`answer-sheet`）を参照。

いまの作り:
- 紙のタブ（`App.tsx` の `sheet` が `'paper' | 'answer' | 'key'`）で開いている紙だけを描く。問題用紙は見えている状態で各ブロックの幅を測って割り付けるので、開いていない紙は描かない
- 印刷の CSS はそろっている。`@page` は B4 横（364mm × 257mm）・余白なし。印刷では `.app-bar`・会話・`.paper-head`（合計・大問の一覧・タブ）を消し、`.page-frame` を一ページずつ改ページする。開いているタブの紙だけが出る
- 解答用紙は `layoutAnswerSheet` がマス目の単位で欄を割り付け、`AnswerSheet` が mm で置く。マス目の欄は `grid-auto-flow: column; direction: rtl` で、マスの `span` を上から下、右の列から左の列の順に並べている
- 割り付けは `Unit` に見出しの網掛け（`shaded`）を持たせており、描く側は小問をたどり直さない
- 作文の問は模範解答を持たない（AI の作文の下書きは `answer` を作らない）
- 会話の `alerts` に、解答用紙が一枚に収まらないことなどを出している
- 締め切りは 2026-11-08 20:00。作り方は、ユーザーとの相談で「ブラウザの印刷から PDF に保存する」「紙ごとに別の PDF」に決めた

## Goals / Non-Goals

**Goals:**
- いまの印刷の仕組みをそのまま使い、PDF にする操作とファイル名だけを足す
- 模範解答つき解答用紙を、解答用紙と同じ割り付けから描き、欄と答えがずれないようにする

**Non-Goals:**
- ボタン一つで PDF ファイルをダウンロードさせること（サーバーで headless Chromium を動かす作り）。関数のサイズ・日本語フォント・起動の遅さがあり、締め切りに対して危うい
- 三枚をまとめた一つの PDF。開いていない紙を同時に描いて割り付けを待つ仕組みが要る
- 問題用紙・解答用紙の割り付けと見た目を変えること
- 作り終えたときの会話の案内（「これでテスト一式がそろいました」のボタン）を変えること

## Decisions

### 1. PDF はブラウザの印刷で作る
- 「（紙の名前）をPDFで出力」のボタンは `window.print()` を呼ぶだけにする。開いている紙はすでに描かれて割り付けも終わっているので、押したときに待つものがない。ボタンと案内は、タブの並び（`.sheet-tabs`、`role="tablist"`）の中ではなく、`.paper-head` の中でタブの並びの隣に置く（tablist の中にはタブしか置かない）。印刷では `.paper-head` ごと消える。
- 狭い画面（375px）では、タブとボタンを一行に並べると入らないので、ボタンと案内はタブの下の行に折り返してよい。
- 別案（html2canvas などで紙を画像にして jsPDF で PDF にする）: `writing-mode: vertical-rl` を正しく描けず、文字も画像になって粗くなる。
- 別案（サーバーで headless Chromium）: Non-Goals のとおり。

### 1-2. 印刷の間も、狭い画面の判定を変えない
- 狭い画面（`max-width: 899px`）では会話と紙面の片方だけを描く。印刷を始めると、このメディアクエリが紙の幅で判定されて当てはまり、会話を開いている扱いになって紙面の列が消え、PDF が白紙になっていた（Playwright の `page.pdf` で確かめた。これまでの e2e はページの数しか見ておらず、見逃していた）。
- 判定を `screen and (max-width: 899px)` にして、印刷の間は狭い画面と見なさない。CSS の狭い画面の規則は、印刷の規則（`.workspace` を block にするなど）で上書きされているので変えない。
- e2e では、PDF に字形が埋め込まれていること（文字が描かれていること）も確かめて、白紙を見逃さないようにする。

### 1-3. 表のページだけ余白をとる
- 紙面のページは `@page` の余白を 0 にして、紙の内側の余白を紙面の側で持っている。模範解答・採点基準の表は二ページ以上に続き、表の内側の余白では二ページ目以降の上端に余白がなくなる。
- 表に名前つきのページ（`page: key`、`@page key { margin: 12mm }`）を付け、表のページだけに余白をとる。名前つきのページが使えないブラウザでは、これまでどおり表の内側の余白にする（`@supports`）。

### 1-4. マス目の線は、一つの要素に実線と点線を混ぜない
- マス目のマスは、左の枠（実線）と下の枠（点線）を一つの要素に持っていた。ユーザーが Edge で印刷した PDF では、作文のマス目の縦の線が一列だけ、下の点線を持つ行で抜け、点線を持たない一番下の行では描かれていた。Playwright の `page.pdf` では倍率や画面の幅を変えても再現しなかったので、抜けた PDF に残った手がかり（枠の種類が一つのマスは描かれる）から直す。
- マスの要素には左の実線だけを持たせ、横の点線はマスに重ねた要素（`::after`）の下の枠で描く。見た目と線の位置は変えない。

### 2. ファイル名はページの題で決める
- `App` で `beforeprint` と `afterprint` を待ち受け、印刷の間だけ `document.title` を「年度　テストの名前　国語　紙の名前」にして、終わったら元の題に戻す。Chrome や Safari は、PDF に保存するときのファイル名の既定をページの題から取る。
- ボタンの中で題を変えるのではなく印刷のイベントで変えるので、⌘P / Ctrl+P で印刷を開いたときも同じ名前になる。
- 紙の名前は、タブの名前の表（問題用紙・解答用紙・模範解答つき解答用紙・模範解答・採点基準）を一か所に置き、タブ・ボタン・題で使い回す。

### 3. 書き込む答えは割り付けで持たせる
- `Piece` と `Unit` に `answer`（その欄に書く答えの文字）を足し、`piecesOf` で決める。記号選択は `choiceLabel(q.correct)`、項目は `it.answer`、穴埋めは空欄の `answer`、抜き出し・記述・短答は `q.answer`。作文は持たせない。
- 網掛けの印（`shaded`）と同じく、どの欄にどの答えが入るかを知っているのは割り付けなので、描く側で小問をたどり直さずに済み、単体テストで確かめられる。
- 割り付けは模範解答つきでもなしでも同じ結果を使う。`AnswerSheet` に `answered` を渡したときだけ答えを描き、題に「模範解答」を足す。欄の大きさは答えから決めていない（字数の指定があればその数）ので、答えを描いても割り付けは変わらない。

### 4. 答えの描き方
- マス目の欄: マスの `span` の中に一字ずつ入れる。マスの並びがすでに縦書きの順なので、i 番目のマスに i 番目の字を入れれば、上から下・右の列から左の列になる。字は縦書きで置き、句読点やかぎかっこは縦書きの形で出す。字は `[...answer]` で数え、サロゲートペアの漢字も一字にする。
- マス目でない欄: 欄の中に縦書きで一行に書く。字の大きさは「マスの大きさの六割」と「欄の高さを字数で割った大きさ」の小さいほうにして、長い答えでも欄からはみ出さないようにする。
- 色は赤（朱書きに近い色）。文字の色は印刷でも落ちないが、念のため `print-color-adjust: exact` を付ける。

### 5. 入りきらない答えは割り付けが見つけ、会話に出す
- マス目の欄で、答えの字数がマスの数より多いものを、`answerOverflows` が「【三】問三・答えの字数・マスの数」の組で集める。マスの数は字数の指定から決まり、マスの大きさによらないので、`SheetLayout` には持たせず小問の欄（`piecesOf`）から求める。`App` はそれを、解答用紙が一枚に収まらない知らせと同じ `alerts` に並べる。
- 描く側は先頭からマスの数だけを描く。マス目でない欄は字を小さくして収めるので、知らせの対象にしない。
- 抜き出し・記述の模範解答は字数の指定を超えないのが前提だが、AI の答えや先生の書き換えで超えることがある。超えた答えを黙って切るより、どこが超えたかを先生に見せる。

### 6. タブを四つにする
- `sheet` に `'answered'` を足し、タブを「問題用紙・解答用紙・模範解答つき解答用紙・模範解答・採点基準」の順に並べる。模範解答つき解答用紙は解答用紙と同じ部品（`AnswerSheet`）で描く。
- 会話のボタンで紙を開く仕組み（`showSheet`）と、案内の文面・ボタンは変えない。模範解答つき解答用紙を開くボタンはないので、型も広げない。

### 7. 確かめ方
- 単体テスト（`layout.test.ts`）: サンプルの欄ごとの答え（三の問二の「イ」、一の問一の項目、四の問二の傍線部の項目、三の問三のマス目、作文は答えなし）と、穴埋めの空欄の答え、字数を超える答えの知らせ。
- e2e: ボタンの名前、`window.print` を差し替えて押したときの題（`beforeprint` の間）と元に戻ること、模範解答つき解答用紙の赤字の答え。印刷で出るものは、Playwright で印刷のメディアにして `page.pdf({ preferCSSPageSize: true })` で PDF を作り、紙ごとのページ数（問題用紙五・解答用紙一・模範解答つき一）とページの大きさ（B4 横）を確かめる。模範解答・採点基準の表も PDF にし、二ページ目以降の上端に余白があるかを見る。
- 既存の e2e は、タブを `getByRole('tab', { name: '解答用紙' })` の部分一致で探している。「模範解答つき解答用紙」のタブを足すと二つ当たるので、タブの指定は `exact: true` にする。
- OS の印刷の画面はエージェントからは操作できない。見た目（赤字の位置、一マス一字、句読点の形）は、e2e と同じ手順で作った PDF を画像にして見て確かめる。印刷の画面で実際に「PDFに保存」を選んだときのファイル名の既定は、先生役のユーザーに確かめてもらう。

## Risks / Trade-offs

- [先生が印刷の画面で送信先をプリンターのまま押してしまう] → ボタンの横に「印刷の画面で『PDFに保存』を選びます」と添える。紙で刷りたい先生にはそのまま印刷にもなる
- [ブラウザによって印刷の画面の操作や、ファイル名の扱いが違う] → デモと確かめは Chrome で行う。Safari もページの題をファイル名に使う。Firefox の縦書きの印刷は、いまの印刷と同じく保証しない
- [問題用紙の割り付けが終わる前にボタンを押すと、空のページが出る] → タブを開いてから紙が見えるまでは一瞬で、見えてから押すので実際には起きにくい。起きたら、割り付けが終わるまでボタンを押せないようにする
- [印刷の画面を開いている間にページの題が変わるので、タブの題もその間だけ変わる] → 閉じたら戻すので害はない
- [赤字は白黒で刷ると灰色になる] → 欄の線は黒のままなので、灰色でも答えは読める
- [題の列に「　模範解答」を足すぶん、年度とテストの名前に使える字数が五字ほど減る] → 題は一行で折り返さず、いまの大きさで三十字ほどまで入る。入らない名前が出てきたら、模範解答つきの紙だけ題の字を小さくする
- [名前つきのページを使えない古いブラウザでは、表の二ページ目以降の上端に余白がない] → デモと確かめは Chrome で行う。一ページ目は表の内側の余白で保つ

## 確認してほしい判断

- 「PDFで出力」のボタンは一つで、開いている紙を出す（紙ごとのボタンは並べず、タブで紙を選んでから押す）。横に「印刷の画面で『PDFに保存』を選びます」と添える
- 模範解答つき解答用紙は四つ目のタブとして画面でも見られるようにし、答えは赤字、題の末尾に「模範解答」と入れる
- 作文の欄は空けておく（作文の模範解答は書き込まない）
- マス目に入りきらない模範解答は、入る分だけ書いて会話に知らせる（勝手に縮めたり省いたりしない）
- 模範解答・採点基準の表も、同じボタンで PDF にできる
